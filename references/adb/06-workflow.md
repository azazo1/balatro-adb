# 操作循环

把 "截图 -> 定位 -> 点击 -> 复查" 固化成固定循环, 是稳定操控无控件界面的关键.

## 标准循环

1. **确认前台**: 确认目标应用在前台, 否则先启动它.
2. **截图**: `exec-out screencap` 存到临时文件.
3. **缩放读全局**: 缩到 1200-1400 px 宽, 看清整体状态 (当前是哪个界面, 数值多少).
4. **定位目标**: 需要精确坐标时, 叠加网格后读数, 或裁剪放大后按裁剪框换算.
5. **验证落点**: 把要点的坐标画在图上, 目视确认落在目标元素上.
6. **点击**: `input tap`, 并 sleep 0.3-0.5 秒.
7. **复查**: 重新截图, 拿行动前写下的**期望**逐条比对 (数值变化, 元素抬起, 界面切换).
   对不上就是这一步没成, 先弄清原因, 不要接着点下一次.

**做完一次关键操作必须复查截图**. 只发事件不看结果, 很容易在错误的界面上继续点击, 把状态越搞越乱.

## 界面状态判读

每次截图先回答三个问题:

1. 现在处于哪个界面 (游戏中 / 盲注结算 / 提现 / 商店 / 菜单)?
2. 关键数值是多少 (分数, 出牌数, 弃牌数, 金钱)?
3. 上一次操作的效果是否已经生效 (动画有没有播完)?

动画没播完时不要继续点击, 等 1-3 秒再截一次.

## 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 截图里坐标对不上元素 | 按竖屏分辨率推算, 或截图方向搞混 | 用 `wm size` 确认覆盖分辨率, 横屏即 2400x1080, 直接用截图坐标 |
| 点击无反应 | 动画未结束, 或点在元素边缘外的空白区 | sleep 后重截, 落点取元素中心 |
| 点到相邻元素 | 元素密集处 (扇形手牌) 的坐标是估算的 | 叠加网格读数, 或画点验证后再点 |
| 截图文件损坏 | 用了 `adb shell ... > file` | 改用 `exec-out` |
| 提示多个设备 | 同一台设备有直连与 mDNS 两条 transport | 所有命令加 `-s <serial>` |

## 批量操作时的写法

把 "点击一个点" 封装成函数, 内建 sleep:

```shell
S=<serial>
tap(){ adb -s "$S" shell input tap "$1" "$2"; sleep 0.35; }
tap 773 690
tap 898 690
```

一串点击后统一截图复查, 而不是每点一次截一次图, 节省往返.

## 记录坐标表

无控件界面的坐标表要靠人工标定, 一旦确认就写下来 (见 [05-balatro-layout.md](05-balatro-layout.md)).
下次操作同一界面时直接复用, 只在分辨率变化 (改了显示大小, 换了设备) 时重新标定.

需要注意: 布局会随内容变化的区域 (例如手牌, 商店货架) **不能** 用固定坐标表, 必须每次读图定位;
固定坐标表只适用于位置固定的按钮和数值区.
